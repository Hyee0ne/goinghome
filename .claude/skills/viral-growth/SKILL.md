# 바이럴 성장 (공유 중심)

목표는 매출이 아니라 **공유가 공유를 낳는 루프**다. 광고비나 인위적인 글 없이, 제품이 만든 결과물이 스스로 퍼지게 설계한다.

근거와 출처는 [references/research.md](references/research.md)에 있다. 숫자를 인용하거나 사례를 들 때는 거기서 확인하고, 출처 신뢰도(1차/언론/약함)를 함께 말한다.
고잉홈 작업이면 먼저 `docs/VIRAL-STRATEGY.md`(현재 전략과 우선순위)를 읽는다.

## 1. 지켜야 할 선 (하지 않는 것)

- **인위적인 커뮤니티 글, 가짜 후기, 지인·부계정 바이럴 시키지 않는다.** 들키면 역바이럴이고 신뢰가 무너진다. 사용자에게 "카페에 글 올려 보세요" 같은 제안도 하지 않는다.
- **숫자를 부풀리지 않는다.** "N명이 만났어요" 같은 카운터는 실제 집계만 쓴다.
- **공유 보상(경품·추첨·기능 해제)은 기본값으로 쓰지 않는다.** 공정위 추천보증 심사지침상 '조건부 대가'도 경제적 이해관계라서 참여자 게시물에 광고 표기 의무가 생길 수 있다. 결과물이 신기해서 공유하게 만든다.
- **유료 협업은 '광고/협찬'을 제목이나 첫 줄에 표기한다** (2024-12 개정 지침).
- **사용자 사진을 서버로 보내는 공유 방식(예: 카카오 uploadImage, 서버 OG 생성)은 쓰지 않는다.** "사진은 기기 밖으로 안 나가요"는 그 자체로 가장 강한 홍보 문구다. FaceApp·Lensa는 개인정보 논란으로 꺾였다.
- 슬픔·안락사를 앞세우지 않는다. 각성도가 낮은 감정은 공유를 줄이고 연민 피로를 부른다.

## 2. 루프를 숫자로 본다

- **K = i × c** (i: 1인당 공유 수, c: 공유 1건이 새로 만드는 사람으로 바뀌는 비율). K가 1을 넘어야 스스로 큰다.
- **사이클 타임(공유 → 받은 사람이 직접 만들어 다시 공유까지 걸리는 시간)이 K보다 중요하다.** 사용자 수는 K^(t/ct)로 불어나서, 사이클 타임을 반으로 줄이면 같은 기간에 몇 자릿수 차이가 난다.
- 측정 없이 감으로 고치지 않는다. 공유 링크에 **세대(gen)와 보낸 경로(src)** 같은 익명 파라미터를 붙이고, 쿠키 없는 집계로 단계별 전환을 센다. 개인 식별 정보는 넣지 않는다.

루프 단계마다 하나씩 병목을 찾는다:

```
만들기 시작 → 첫 결과(놀람) → 공유 버튼 → 공유 완료 → 미리보기 클릭 → 받은 사람의 첫 반응(aha) → 내 것 만들기 → 다시 공유
```

## 3. 공유 결과물 설계 (가장 큰 지렛대)

결과물이 곧 광고다 (Hotmail 서명, TikTok 워터마크, Spotify Wrapped와 같은 구조).

- **내 것으로 만든 결과물**: 내 아이, 내 얼굴, 내 취향이어야 정체성을 드러내는 공유가 된다 (공유 동기 68%가 "내가 누구인지 보여주려고").
- **각성도 높은 긍정 감정**: 놀람, 웃음, 귀여움. "진짜 웃었어!"를 첫 1초 안에 보여 준다. 첫 프레임부터 움직여야 한다.
- **형식**: 9:16 세로 mp4(H.264)가 릴스·쇼츠·틱톡·스토리를 다 덮는다. 오락용은 7~15초가 적당하고, 루프되면 6초도 된다. 소리 없이 봐도 이해되게 짧은 자막을 넣는다. iOS Safari의 MediaRecorder는 mp4만 녹화한다.
- **세이프존**: 1080×1920 기준으로 위 약 14%, 아래 약 35%, 오른쪽 약 15%는 플랫폼 UI가 덮는다. 워터마크와 주소는 그 밖에 둔다.
- **워터마크는 작게, 자기 이름/주소로.** 인스타는 다른 앱 로고가 박힌 릴스를 추천에서 빼는 경향이 있다(자기 브랜드는 괜찮음). 스크린샷이나 화면 녹화로 재공유돼도 출처가 남게 주소를 넣는다.
- **엔드카드는 짧게(0.5~1.5초), 궁금증과 행동을 묶는다**: "너도 쓰다듬어 볼래? goinghome…".
- **정적 공유물(이미지/텍스트)도 하나 둔다**: 영상을 못 받는 곳(카톡 미리보기, X, 스레드)용 1:1 또는 2:1 이미지와 한 줄 문구.
- **결과가 나쁘면 공유 단계 전에 막는다.** 언캐니하거나 깨진 결과가 퍼지면 역바이럴이다.

## 4. 채널별 현실 (한국)

- **카카오톡이 주 채널**(국내 MAU 약 4,800만, 공유의 대부분은 DM·단톡 같은 '다크 소셜').
  - 영상은 템플릿에 못 넣는다. 썸네일 이미지와 링크로 보낸다.
  - **OG 태그가 없으면 미리보기가 비어 클릭이 크게 준다.** og:title·og:description·og:image(JPG/PNG, 800×400 또는 800×800)를 모든 공유 대상 페이지에 넣는다.
  - 카카오는 OG를 캐시하고, 이미지 캐시는 디버거로도 안 지워진다. 이미지를 바꿀 땐 `?v=2`처럼 URL을 바꾼다.
  - Kakao JS SDK 공유는 하루 3만 건까지 무료다(초과분 과금). 넘치면 `navigator.share`나 링크 복사로 자연스럽게 넘긴다. SDK를 쓰려면 앱 키와 도메인 등록이 필요하다.
  - **카톡 인앱 브라우저에서는 blob 다운로드와 카메라·녹화가 자주 막힌다.** 받은 사람이 "만들기"로 넘어갈 때 외부 브라우저로 열도록 안내한다(`kakaotalk://web/openExternal?url=`).
- **인스타·틱톡·쇼츠**: 웹에서 바로 올리는 공식 경로가 없다. `navigator.share({files})`를 먼저 시도하고, 안 되면 "영상 저장 → 앱 열어 올리기" 안내로 넘어간다. 실기기에서 확인한다.
- **스레드·X**: 웹 인텐트는 텍스트와 링크만 된다.

## 5. 받은 사람 경험 (c를 키우는 곳)

- 링크를 열고 **1~2초 안에 무언가 반응해야** 한다. 모바일 로딩이 1초에서 3초로 늘면 이탈 확률이 32% 오른다. 무거운 것은 뒤로 미룬다.
- **가입 없이 바로 체험**한다. 바로 그 장면을 직접 해 보게 한다(보기만 하고 끝나지 않게).
- **보낸 사람과의 연결 문구**: "친구가 쓰다듬은 아이와 닮은 친구예요". 지인 추천 신뢰가 가장 높다.
- "너도 만들어 봐" 초대는 **첫 aha 직후**에 띄운다. 너무 늦으면 사이클 타임이 늘고, 너무 이르면 체험을 막는다. 시점은 측정해서 정한다.

## 6. 대의(cause)와 엮기 — 공유는 밝게, 행동은 한 마리로

- 공유물은 웃음과 귀여움으로 만든다. 입양 메시지는 공유의 동력이 아니라 **받은 사람 경험 안**에 둔다.
- **"내 것과 닮은 진짜 아이" 매칭은 검증된 방식이다**: Pedigree Adoptable Mask(첫 주 1,750만 도달), PetRescue PetMe, Rescue Doodles(매칭 1.8만 건), 국내 제일기획 독플갱어(2주 2만 명). "닮은 이유"(털색, 귀)를 보여 주면 공유 포인트가 된다.
- **식별 가능한 한 마리**: 통계("연 9.5만 마리")보다 "이 아이"가 행동을 끌어낸다. 실제 공고 마감 D-n은 사실 그대로의 긴급성이다.
- **슬랙티비즘 막기**: 공개적으로 공유만 하고 나면 실제 행동이 준다. 공유 앞뒤에 혼자 하는 작은 행동("공고 보기", "보호소 번호 보기")을 둔다.
- **입양 장벽 해소**: 망설이는 이유 2위가 "절차 정보 부족"(27.8%)이다. 3단계 안내와 연락처를 바로 보이게 둔다.
- 공유당 기부는 **실제 기부처가 있을 때만** 쓴다.

## 7. 정당한 증폭 경로 (씨앗 공유자)

구글 셀카-명화 매칭도 셀럽 공유로 터졌다. 인위적인 글 대신 **실제 이해관계자가 자기 이름으로 쓰고 싶은 것**을 만들어 준다.

1. **SNS를 운영하는 보호센터에 콘텐츠를 무료로 제공**: 그 센터 아이의 움직이는 영상. 그들의 공식 계정에 올라가는 진짜 콘텐츠다.
2. **보도자료**: 동물 전문지와 IT 매체. 기사 포인트는 "사진은 기기 밖으로 안 나감", "공공데이터 공고 연결", "손으로 쓰다듬는 웹".
3. **유기견 출신 반려견 계정과 협업**: 대가가 있으면 광고 표기를 한다.
4. **오프라인 행사**: 반려동물 축제 현장 QR. 즉석에서 쓰다듬기 체험을 하게 한다.
5. **시즌·새 요소 정기 추가**: Wrapped(매년 새 요소), MyHeritage(새 기능 연속)처럼 다시 공유할 이유를 만든다. 실제 공고견이 계속 바뀌는 것 자체가 새 콘텐츠다.

## 8. 작업 방식

기획이나 점검을 요청받으면:

1. 현재 루프를 실제 코드와 화면으로 따라가 보고(공유 함수, OG 태그, 녹화 형식, 받은 사람 화면), 단계별 병목을 적는다. 추측하지 말고 파일을 연다.
2. 개선안은 **루프 단계 · 기대 효과(어떤 숫자가 움직이나) · 비용 · 원칙 위반 여부**로 정리한다. 측정 방법을 함께 적는다.
3. 우선순위는 "사이클 타임과 c를 크게 바꾸는데 싸고 원칙에 맞는 것"부터 둔다.
4. 구현이 다른 담당(서비스·기술) 영역이면 직접 고치지 말고 전달할 요청서로 쓴다.
5. 사용자가 정해야 하는 것(도메인, 외부 계정 등록, 외부 연락)은 따로 모아 묻는다. 외부 연락(보호소, 언론)은 초안까지만 만들고 보내는 것은 사용자가 한다.
